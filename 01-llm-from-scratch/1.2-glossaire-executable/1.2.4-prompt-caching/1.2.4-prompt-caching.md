## L'essentiel

Chaque appel re-paye tout le préfixe (system, outils, exemples) — vu en
[1.1.1](../../1.1-socle-sans-framework/1.1.1-chat-cli-historique-contexte/1.1.1-chat-cli-historique-contexte.md).
Le prompt caching évite de **recalculer ce préfixe stable** : le serveur
conserve l'état interne (KV cache) du début du prompt et ne retraite
que ce qui change. Pour un agent qui boucle avec le même system prompt,
c'est l'économie dominante.

## Le savoir

- **Ce qui est caché** : le **KV cache** — les représentations
  clés/valeurs de l'attention calculées pour chaque token du préfixe.
  Le re-calcul de ces représentations est précisément la phase chère
  (« prefill ») ; les réutiliser fait passer le coût du préfixe à ~0.
- **La condition absolue** : le cache marche par **préfixe exact**. Un
  seul octet changé au début invalide tout ce qui suit — d'où la règle
  d'architecture : *stable au début (system, outils, exemples),
  variable à la fin (question, contexte du tour)*.
- **Trois incarnations** :
  - **API cloud** (Claude : `cache_control`) : points de cache
    explicites, préfixe facturé ~10 % de son prix en lecture, TTL
    limité ;
  - **serveurs locaux** (Ollama : `keep_alive` + réutilisation de
    session ; vLLM : *automatic prefix caching*) : même mécanique,
    gratuite, limitée par la VRAM ;
  - **multi-tours** : la conversation entière est un préfixe croissant
    — le cache transforme O(n²) cumulés en ~O(n).
- **Lien module 3** : un agent Pi qui fait 30 tours avec 2 000 tokens
  de system/outils re-payerait 60 000 tokens de prefill — le caching
  est ce qui rend les agents économiquement viables.

## En pratique

L'exercice (~50 lignes) : chronométrer avec httpx le même prompt de
~2 000 tokens envoyé deux fois à Ollama (modèle chargé, session
réutilisée) — mesurer TTFT froid vs chaud ; puis varier un mot **au
début** vs **à la fin** du prompt et observer l'asymétrie.

## Pièges connus

- Timestamp ou ID de session dans le system prompt : invalidation du
  cache à chaque appel, silencieuse et coûteuse.
- Outils déclarés dans un ordre non déterministe (dict non trié) →
  préfixe instable — sérialiser de façon canonique.
- Confondre prompt caching et cache de *réponses* : on économise le
  prefill, la génération reste payée et reste probabiliste.

## Question d'entretien

> « Comment réduire le coût d'un agent qui fait 50 appels avec le même
> prompt système ? »
> Prompt caching : préfixe stable en tête, points de cache (ou serveur
> avec prefix caching), et mesurer TTFT/coût avant-après — puis
> seulement discuter compaction et modèle plus petit.
