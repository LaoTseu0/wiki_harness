# P.2.1 Un post par module

## L'essentiel

Un post par module (blog perso ou dev.to), en anglais. Le post force la
clarté — on ne publie bien que ce qu'on a vraiment compris — et rend le
travail *trouvable* par les bons recruteurs. Le [post
« anatomy »](../../../07-multimodal/7.1-documenter-existant/7.1.2-post-anatomy/7.1.2-post-anatomy.md)
du module 7 en est le gabarit.

## Le savoir

- **Un angle par post, tiré du différenciateur du module** :
  - module 2 → « Building a RAG over my homelab docs, **with evals** »
    (les evals, le différenciateur n°1) ;
  - module 4 → « vLLM vs Ollama on a 6 GB consumer GPU » (les courbes) ;
  - module 5 → « Writing an MCP server *and* client from scratch » ;
  - module 7 → « Anatomy of a fully local voice assistant ».
  L'angle est toujours le chiffre ou la démonstration, jamais le
  tutoriel générique (« what is RAG » est déjà écrit mille fois).
- **La structure = le canon README**
  ([P.1.1](../../p.1-repos-publics/p.1.1-github-public/p.1.1-github-public.md)) :
  problème → architecture (schéma) → métriques → « what I'd do
  differently ». Un post et un README partagent le même squelette —
  écrire l'un aide l'autre.
- **La cadence réaliste** : un post *à la fin* de chaque module, pas
  en plus du travail mais **comme clôture** du module (le module n'est
  « fini » que publié). Sortie précoce ici aussi
  ([1.3.6](../../../01-llm-from-scratch/1.3-framework-maison/1.3.6-sortie-precoce-semver/1.3.6-sortie-precoce-semver.md)) :
  un post daté et imparfait bat un brouillon parfait.
- **Les canaux** : blog perso (contrôle, SEO à soi) et/ou dev.to
  (audience existante) ; cross-post vers r/LocalLLaMA quand le sujet
  s'y prête ([roadmap §7](../../../roadmap.md)).

## En pratique

À chaque module livré : un post à l'angle « chiffre/démo », structure
canon, schéma réutilisé du README, relu par un anglophone, publié et
lié depuis le portfolio et le [pitch](../../p.3-pitch/p.3-pitch.md).

## Pièges connus

- Le post-tutoriel générique : sans angle personnel ni chiffres, il se
  noie dans les mille autres — l'angle vient de *ton* projet.
- Attendre d'avoir « le temps d'écrire » : le post fait partie du
  module, pas d'un après hypothétique.
- Écrire en français « pour aller plus vite » : le portfolio public
  visé est international — anglais.

## Question d'entretien

> « Écrivez-vous sur votre travail ? »
> Un post par module, angle chiffré (RAG with evals, vLLM benchmark,
> MCP from scratch), structure problème/archi/métriques/recul, en
> anglais — publier fait partie de finir un projet, pas d'un extra.
